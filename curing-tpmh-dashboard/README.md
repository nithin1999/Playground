# Curing TPMH Dashboard

Project dashboard for the Curing TPMH / 2-operator staffing improvement project.

## Current status
Design/validation phase. No 2-operator pilot success or permanent manpower reduction is claimed. Tricycle remains closed after Safety rejection.

## Evidence retained
- Comparable August alarm set: 8,732 events from 55 presses; A65 supplied data are September-period and remain outside raw August totals.
- Same-minute starts: 0 alarms 81.5%, 1 alarm 15.2%, 2 alarms 2.86%, >2 alarms 0.50%.
- Alarm duration is not operator hands-on labor; actual response labor is still required.

## Latest improvement — quantify travel burden before freezing two zones
The future state already calls for geographic zones and point-of-use staging, but the zone design must not be frozen from press count or workload alone. In a machine-intensive process, operator movement is partly signal-driven, so travel itself is capacity demand. Add a **Travel Burden / Motion Loss study** before final zone freeze.

For representative baseline windows, record origin, destination, reason, start/end or distance, and whether the trip was: (1) required abnormal-response travel, (2) required routine route, or (3) avoidable fetch/search/document/material travel. Build a spaghetti overlay by operator/zone and a from-to matrix for the highest-frequency routes.

Use the results to redesign point-of-use locations and zone boundaries. Evaluate candidate two-zone layouts on **occupied work + peak/concurrent demand + travel minutes/distance**, not equal press count. Report total walking minutes and distance per 100 running press-hours, plus avoidable fetch/search trips per shift. Keep alarm-response travel visible rather than classifying all walking as waste; the improvement target is unnecessary motion and poor routing.

This is a design/measurement improvement only. No travel reduction is claimed until a future-state layout is physically tested and measured. The rejected tricycle is not reopened; the preferred hierarchy is remove trips, shorten trips, improve point-of-use staging/visual information, then validate the resulting walking demand.

## Best current strategy
1. Map presses and actual travel; classify required signal-driven travel vs avoidable motion.
2. Balance two geographic zones by occupied workload, peaks/concurrency and travel—not press count.
3. Relocate feasible documents/materials/tools to point of use and define the future-state route.
4. Standardize predictable routine work and define protected timing/priority.
5. Keep abnormalities signal-driven with explicit ownership, cross-support and escalation.
6. Verify two-deep critical-task qualification across crews and relief windows.
7. Prove break relief and time-phased capacity margin including measured travel.
8. Freeze measurement definitions, Leader Standard Work, SIC cadence and escalation authority.
9. Collect a context-characterized 3-op baseline using the same SIC, intervention, dependency-rate, backlog-aging and travel measures.
10. Shadow 2-op and measure concurrent alarm demand, staffing-dependent third-person support, displaced work, backlog aging, carryover and travel burden.
11. Pareto overload, interventions, qualification gaps, routing overrides, travel losses and backlog causes; revise zones/standard/support rules.
12. Run sustained A/B/C/D rotation; move to true 2-op only after representative conditions pass without hidden support, recurring negative capacity margin, protected-work failure or persistent backlog.

## Pilot gates
- **Gate 0 — Data/design:** mapped layout, normalized alarm evidence, travel-burden study, workload/travel-balanced candidate zones.
- **Gate 1 — Standard work/skills:** routine-work matrix, response matrix, verified critical-task coverage, future-state route/point-of-use plan.
- **Gate 2 — Relief/capacity:** break-relief matrix and preliminary 30-minute capacity-margin profile including measured travel.
- **Gate 3 — Management/measurement:** measurement dictionary, observer check, Leader Standard Work, visual controls, SIC ownership, intervention taxonomy.
- **Gate 4 — Baseline/context:** current 3-op state measured with identical definitions, SIC, dependency-rate, backlog-aging and travel measures.
- **Gate 5 — Shadow 2-op:** capture busy/free state, response labor, interventions, relief exceptions, displaced work, recovery aging and route exceptions.
- **Gate 6 — Revise:** Pareto causes and revise the operating system.
- **Gate 7 — Sustained trial:** full crew rotation without hidden support, recurring overload, missed protected work or persistent carryover.
- **Gate 8 — True 2-op/control:** demonstrated acceptance across representative conditions; controlled standard work, skills, relief, escalation, SIC and control plan.

## Immediate next action
Run a **representative travel-burden observation** using the existing floor map: log origin → destination → reason → time/distance for each operator trip, then draw a spaghetti overlay and from-to frequency matrix. Separate required alarm/routine travel from avoidable fetch/search trips. Use that evidence to propose two candidate zone boundaries and point-of-use changes before freezing the 2-operator layout. Do not set an arbitrary walking threshold; compare current and candidate layouts on measured exposure.
