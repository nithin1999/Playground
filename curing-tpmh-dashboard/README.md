## Latest improvement — Support Displacement Ledger
A 2-operator pilot can look successful if another employee temporarily helps Curing, while the helper's own work is delayed elsewhere. Therefore every incremental support event must track both the help received **and the work displaced at the donor role**.

For each support event record:
`time | helper/role | reason called | support start/end | support people-min | helper's normal work displaced? | displaced task | backlog/delay created in donor role | replacement used? | donor role restored time | outcome`

### Interpretation
- Support with no displaced donor work may represent legitimate planned flex capacity, but it must still be identified.
- Repeated support that delays the helper's normal work is **labor displacement**, not independent 2-operator success.
- If the helper needs a replacement, follow the chain until no additional staffing-dependent displacement remains; avoid double-counting the same minutes.
- Support concentrated in one work family points to a targeted skill/ownership/motion countermeasure.
- Support concentrated in breaks points to relief design.
- Rare plant-authorized rescue during severe abnormalities should be classified as containment, not automatically treated as evidence for permanent third-operator staffing.

Use `Adjusted TPMH = Cured Tires / (scheduled Curing labor-hours + incremental staffing-dependent support hours)` as a secondary diagnostic. Do not count normal leadership presence or already-planned shared services as incremental labor unless the pilot causes additional work or displacement.

## Standard-Work Conformance / Deviation Log
For each 15-minute window record standard followed?, deviation, reason, workaround and consequence. Classify **STANDARD FOLLOWED / JUSTIFIED DEVIATION / STANDARD NOT PRACTICAL**. Pareto recurring justified deviations rather than treating them as operator noncompliance.
