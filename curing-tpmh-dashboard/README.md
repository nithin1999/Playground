## Latest improvement — Trigger-Based Abnormal Response Ladder
The 2-operator design now needs an explicit **reaction standard**, not just an hourly status board. During Thursday, an abnormality should move through the existing plant-authorized response chain without relying on observer judgment or ad-hoc operator negotiation.

Use this sequence as the pilot logic, while existing Safety/Quality rules remain authoritative:

**NORMAL ROUTE → ABNORMALITY VISIBLE/CALLED → PRIMARY OWNER RESPONDS → FLEX OWNER ASSISTS WHEN THE DEFINED PLANT CONDITION REQUIRES IT → FLOOR LEADER RESPONDS TO UNRESOLVED/COMPETING DEMAND → CONTAINMENT/RESCUE UNDER EXISTING PLANT RULES → BACKLOG RECOVERY → NORMAL ROUTE**

Do **not** invent time thresholds before the pilot. Use existing plant escalation requirements where they exist. Where no formal trigger exists, record the observed trigger and response time rather than silently creating a new standard.

### Reaction record
For every meaningful abnormality retain:
`time visible/called | zone/press | abnormality | primary owner | primary arrival | flex called | flex arrival | leader called | leader arrival | rescue/containment | competing work | backlog created | normal route restored`

This separates four failure modes that can otherwise all look like “2 operators were too busy”:
1. **Detection/visibility failure** — abnormality was not made visible promptly.
2. **Ownership failure** — it was visible but responsibility was unclear.
3. **Response-capacity collision** — qualified owners were already committed elsewhere.
4. **Recovery failure** — the abnormality was handled, but protected work/backlog did not return to normal.

Leader/flex response is not automatically evidence that 2-op failed. Classify whether the help is **normal baseline leadership/support** or **incremental capacity required specifically because of the 2-op design**, and retain people-minutes.

## Hour-by-Hour Demand-to-Capacity Board
For each hour capture:
`Hour | Plan | Actual | Running presses | Abnormal events | Op1 direct work min | Op2 direct work min | Walk/retrieval min | Queue episodes | Oldest backlog | Relief/support min | Independent 2-op min | Major cause`

Use GREEN only when demand is handled independently and required protected work remains current; YELLOW for temporary backlog/flex/incremental support with recovery; RED for containment/rescue, unresolved required backlog, or an applicable plant safety/quality/process limit. Existing plant requirements determine overdue/containment conditions.
