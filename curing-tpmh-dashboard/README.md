## Latest improvement — Protected-Work Due-Time Visual Control
A machine-intensive 2-operator design must not rely on memory for periodic/check work while operators react to alarms. Before the pilot, convert the verified protected/periodic task list into a small visual due-time queue: `task | owner | due/interval | NEXT/DUE/OVERDUE | completed time | displaced by | recovered time`.

Use only the real plant-required frequencies and due times. When an abnormality interrupts normal work, respond under the existing reaction rule, then check due protected work before returning to the normal route. This makes deferred work visible and distinguishes alarm clearance from full system recovery.

Post-pilot, compare protected-work lateness with recovery debt, breaks and support events. Repeated overdue work while both operators are committed indicates capacity/recovery pressure; overdue work while an operator is available points instead toward ownership, visibility, route or training. If a due-time requirement is unknown, mark it UNKNOWN rather than inventing a standard.
