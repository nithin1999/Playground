Latest improvement — recovery backlog aging

The prior routine-work control identifies work displaced by abnormalities. The new control tests whether that displaced work forms a growing recovery queue. A good shift-end TPMH result is not enough if routine work repeatedly crosses SIC blocks, ages, requires hidden support, or remains at shift end.

At displacement: record task, time, plant-required timing/priority if defined, and recovery owner.
Every 2-hour SIC: show open task count, open work minutes, oldest item age, recovered tasks, carryover, and outside-support minutes used for recovery.
At shift end: any unrecovered protected work remains visible; do not reset the board to zero.

No arbitrary backlog/aging threshold is assigned. Existing YTMM safety/quality/process deadlines govern where available; other triggers require baseline/shadow evidence.

Best current strategy

  1. Map presses; balance zones by occupied workload, peaks and travel.
  2. Standardize predictable work and define protected timing/priority.
  3. Use signal-driven abnormalities with explicit ownership/cross-support/escalation.
  4. Verify two-deep critical-task coverage across crews and relief windows.
  5. Prove break relief and time-phased capacity margin.
  6. Freeze measurement definitions, Leader Standard Work, SIC and escalation authority.
  7. Collect context-characterized 3-op baseline with the same backlog-aging control.
  8. Shadow 2-op: measure concurrent demand, interventions, displaced work and recovery aging.
  9. Pareto overload/backlog causes → revise → sustained A/B/C/D rotation → true 2-op only after gates pass.

Next action

Add a Recovery Backlog / Aging Strip to the six 2-hour SIC blocks. Start with GIP/scan, checks/documentation, replenishment, planned manual work, monitoring and relief obligations. Use it in both baseline and shadow collection.
