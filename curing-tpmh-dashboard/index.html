Latest improvement — Surge Recovery / Queue-Drain Test

A temporary overload does not by itself prove that two operators are infeasible. The stronger test is whether they can return the system to normal after a demand burst without hidden labor, missed required work or persistent backlog.

Use the existing Pending Work board and 15-minute windows. For each surge identify surge start → peak backlog → recovery start → recovery complete, while keeping leader/flex/outside-support minutes separate.

Measure: Net Queue-Drain Rate = reduction in pending due-work minutes / recovery minutes; Time to Recover; Residual Debt at break/handoff/shift end; and Independent Recovery yes/no. Do not invent a numeric recovery target—judge against real due-time requirements, plant reaction standards and matched historical conditions.

Diagnostic logic

Short overload followed by rapid independent recovery with no late protected work may be absorbable. Backlog that continues growing after demand normalizes indicates a real capacity, qualification, dispatch, route or work-content constraint. Recovery that requires leader/flex labor is hidden staffing dependency. Queue drain achieved by delaying protected work is displacement, not recovery. Slow recovery with high motion loss points to layout/point-of-use; slow recovery with asymmetric loading points to zone/PRIMARY-FLEX balance.

Validate Maintenance Support first and check whether task times already contain normal walking/restart effects.

Best current strategy

  1. Freeze people, zones, routes, qualifications, relief and reaction rules.
  2. Freeze/confidence-tag the 736-min model; validate Maintenance Support first.
  3. Map skill-restricted/two-person work and assign PRIMARY/FLEX ownership, handoff and dispatch priority.
  4. Scenario-walk breaks, simultaneous abnormalities, skill conflicts, interrupted work and cross-zone response.
  5. Run Thursday with timestamped work, response milestones, 15-minute windows, Pending Work, saturation, support, interruption and route-deviation tags.
  6. Calculate Interval Load, qualification feasibility, Interruption Tax, Pending WIP, Route-Deviation Minutes and Surge Recovery / Queue-Drain Rate.
  7. Build NORMAL / BREAK-RELIEF / SURGE-SATURATION operator balance.
  8. For every surge, verify independent recovery to the pre-surge Pending Work level before due-time violations or handoff.
  9. Normalize for press-hours, events, mix and downtime; compare matched shifts.
  10. Correct only the demonstrated constraint and repeat representative exposure before permanent change.

Before Thursday, define the pre-surge baseline for the Pending Work board. During the pilot, when a queue forms, continue observing after the alarm clears until Pending Work returns to that baseline. The recovery period is part of the staffing test.
