Latest improvement — Response-Time Service-Level Curve

TPMH, concurrency and saturation do not show whether abnormalities are answered quickly enough. For each meaningful abnormal call capture: event/call → awareness → response start → arrival → containment/first effective action → clear → route restored, plus PRIMARY/FLEX/support source.

After the pilot report median, 90th percentile and maximum response time and compare the distribution with real plant requirements and matched staffed-shift performance. No arbitrary response threshold is invented.

Why it matters

Slow response in distant zones suggests route/layout loss; during breaks suggests relief weakness; after delayed ownership transfer suggests dispatch/handoff weakness; while both operators are committed suggests capacity/surge pressure. A good average with a poor upper tail exposes fragility that shift-average TPMH can hide.

Best current strategy

  1. Freeze roles, routes, qualifications, relief and plant reaction rules.
  2. Assign PRIMARY/FLEX ownership, handoff and dispatch priority.
  3. Scenario-walk breaks and abnormal combinations.
  4. Run Thursday with timestamped response milestones, workload, queues, saturation and support.
  5. Build response-time curves by zone, break, saturation and ownership state.
  6. Reconcile break and donor-role debt.
  7. Build Base versus Surge work-combination views and Recovery Debt.
  8. Normalize for press-hours, events, mix and downtime and compare matched shifts.
  9. Fix only the demonstrated constraint and repeat representative exposure.

Immediate next action

Synchronize observer timestamps before Thursday and add event/call, awareness, response-start, arrival, containment, clear and route-restored fields. Prefer actual system timestamps over recollection.

Critical gaps
