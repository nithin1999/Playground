Latest improvement — Pending Work / Recovery Queue

The interruption test identifies fragmented work, but interrupted or legitimately deferred required work can still disappear into operator memory. Treat unfinished required work as visible operational WIP.

During the pilot, create one live Pending Work / Recovery Queue. Add a row only when required work is interrupted or legitimately deferred: task, zone/press, time entered, real due requirement if applicable, owner, reason deferred, status. Remove it only when completed or formally handed off.

Measure: Peak Pending WIP, Pending WIP minutes, Oldest Pending Age, carryover at breaks/shift end, and unowned open work. Do not invent a numeric WIP limit before observing the process.

Diagnostic logic

WIP rising while both operators are committed supports a surge/capacity constraint. WIP rising while usable qualified capacity exists points toward dispatch, balance, ownership or visual-control failure. Break-concentrated WIP points toward relief design. Repeated carryover of one task family points toward sequencing, protected-window or workload-model issues.

Maintenance Support contributes 336 min (45.7%); Alarm Response + Maintenance Support + Bladder Support + Changeover Support total 548 min (74.5%). Validate Maintenance Support first and check whether existing task times already contain interruption/restart effects to avoid double counting.
